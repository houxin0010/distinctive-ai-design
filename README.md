# 有个性的 AI 设计 · Distinctive AI Design

**中文** | [English](README.en.md)

一个为 Codex 编写的设计工作流 skill，帮助 AI 从常见模板中走出来，为网页、应用和游戏界面建立清晰、有辨识度的视觉方向。

它把设计任务组织成 **探索 → 定义 → 交付**：先拓宽创意，再把方向落实到界面，最后通过实际截图和减法精修改善结果。视觉选择始终围绕目标用户和主要任务展开。

## 适用场景

- 为新产品、落地页或游戏界面探索视觉概念。
- 重新设计一个功能可用、但缺少个性或层级的页面。
- 改善重复卡片、机械布局和无目的装饰带来的模板感。
- 在已有审美方向下，完善字体、构图、素材与交互的一致性。
- 使用真实截图获得具体的设计反馈，再实施有限轮次的改进。

普通功能修改、局部样式修复和已经明确的小问题，可以直接处理，不需要完整启动探索流程。现有品牌规范、用户指定方向和项目技术栈始终是约束。

## 核心方法

| 方法 | 如何使用 | 预期产物 |
| --- | --- | --- |
| 多方向探索 | 提出约三个在构图、信息组织、字体或交互隐喻上不同的概念 | 简短、可比较的方向说明 |
| 具体的创意 brief | 把用户的喜好、反感和产品用途转成可执行约束 | 统一的设计依据 |
| 真实随机种子 | 陷入重复模板时，用本地随机源引入节奏、分组或对比灵感 | 新的探索线索，种子不显示在产品中 |
| 独立截图评审 | 在允许委派时，让新的评审上下文查看截图与 brief | 具体问题、调整建议与参考评分 |
| 按需生成媒体 | 当图片或视频能承担核心表达时使用，检查其与页面的融合 | 有用途的视觉素材与回退方案 |
| 减法精修 | 删除重复说明、无用容器和竞争注意力的效果 | 更清楚的层级与主要操作 |

这些方法是可选择的工具，不要求每次任务都使用随机种子、生成图片或制作视频。

## 快速开始

在目标项目中提供页面位置、主要任务与约束，然后调用 skill：

```text
使用 $distinctive-ai-design 改进当前首页。
目标用户是独立开发者，主要操作是查看产品功能并开始试用。
先提出三个真正不同的视觉方向，再选择最合适的一版实现。
沿用现有技术栈和组件，依据实际截图评审并精修。
```

skill 的执行指令目前为中文；可以用中文或英文提出任务。英文 README 是使用说明，不是单独的英文版 skill。

## 使用示例

### 先探索，不实施

```text
使用 $distinctive-ai-design 为我的办公题材游戏设计主菜单方向。
我想要克制、略带幽默的办公室氛围，避免霓虹和过度拟物。
给出三个构图与交互组织不同的概念，说明各自如何突出“开始游戏”。
本轮只提供概念与 brief，等我选择后再实现。
```

### 在已有方向下完善页面

```text
使用 $distinctive-ai-design 改进产品详情页。
保留现有品牌色和内容，采用偏编辑式的布局与清楚的字体层级。
无需重新探索方向。先实现关键视图，再用截图找出最影响效果的三个问题。
```

### 专注于减法精修

```text
使用 $distinctive-ai-design 精修当前仪表盘。
保留业务功能与必要状态提示，检查重复说明、装饰容器和无意义发光。
优先通过删减和调整层级改善体验，不增加新的视觉素材。
验证主要操作和窄屏布局，并说明哪些部分未验证。
```

### 按需使用视觉素材

```text
使用 $distinctive-ai-design 改进这个产品展示页。
如果一张主视觉能帮助表达产品用途，就使用当前可用的图像生成工具。
让素材与页面构图、配色和留白一致；普通动效使用现有平台能力。
不要接入新的付费服务，缺少生成能力时使用可完成主任务的静态方案。
```

## 工作流程与交付

1. **探索**：读取现有界面与约束，确定用户、主要任务和目标感受；方向不明确时提出可比较的概念。
2. **定义**：将选定方向写成 brief，落实到代表性页面或关键状态，使用现有技术栈与组件。
3. **评审**：捕获运行中的界面截图，检查构图、层级、字体、素材整合和细节；优先修正一至三个主要问题。
4. **交付**：删除不服务于用途的元素，验证主操作、相关状态和窄屏表现，报告结果与限制。

brief 通常包含：用户与主要任务、目标感受、视觉隐喻、构图与信息层级、色彩与字体、关键交互、避免的元素，以及第一版最小范围。

完成后应获得实现或设计产物、主要调整说明，以及实际验证的证据。审美评价与功能验证分别报告；有截图不代表已经证明交互、性能或无障碍行为正常。

## 评审边界与环境要求

| 能力 | 何时需要 | 不可用时 |
| --- | --- | --- |
| 项目文件访问与实现工具 | 修改实际界面 | 保持任务为概念或设计建议，说明范围 |
| 运行环境与截图工具 | 验证最终视觉结果 | 标注视觉验证未完成 |
| 独立子代理 | 当前任务允许委派，并需要独立评审 | 按同一维度自查，明确这是自查 |
| 图像或视频生成 | 素材对核心表达有明确价值 | 使用已有素材或静态方案，说明限制 |

skill 本身不附带浏览器、生成服务、API 密钥或独立评审模型，也不固定框架、模型版本或付费平台。可选能力取决于当前运行环境、授权与预算。

评审者查看截图、用户任务、审美 brief 和必要参考图，不接收代码、历史解释或目标分数。先进行最多两轮，每轮修正最重要的问题。若不收敛，报告剩余缺口并重新考虑方向，避免无限追分。`9/10` 仅可作为内部愿景，不能作为上线保证或客观质量认证。
